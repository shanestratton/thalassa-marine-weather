# Offline regional-current publisher foundation

This module stages public normalized forecast vectors locally. It has no provider transport, command-line runner, upload, release write, timer, production key or activation switch. The application policy remains closed and its trusted-key set remains empty. Generated fixture success is not a deployed current forecast capability.

`buildRegionalGeneration(series, issuedMs, keyId, privateKey)` accepts at most two independently identified models and eight fixed two-degree regions. It uses the same strict app contract to validate clocks, true east/north m/s vectors, surface depth, provider cadence and known masks. Ocean and tidal fields stay separate; RTOFS tidal data is refused. It never fills unknown cells, clamps time, rotates an unverified grid or resamples geometry. Issuance is an explicit source timestamp, not a replacement for a missing provider run.

The content generation is deterministic over the original source identities and exact normalized bytes, independent of input ordering. Every region/model THCS file preserves its own source hash, dataset, run, valid times and masks. Signed Ed25519 manifests reference exact immutable file lengths/hashes. The whole input decoded budget and whole encoded output budget are each8MiB, and each object remains within the app's2MiB asset limit. No existing thirteen-frame display object or namespace is changed.

`stageRegionalGeneration` only creates a fresh caller-owned absolute directory. It independently rechecks paths, file hashes and actual aggregate bytes before writing. It writes and reads back every immutable asset before writing any signed manifest, yields between files to observe cancellation, and checks a60-second cooperative deadline. A failure leaves its partial local directory without `STAGED.json`; it does not delete or publish it. `STAGED.json` is a bounded file inventory, explicitly marked `publication:false`; exact provider identity remains inside the hashed THCS headers.

A real provider/publisher job still needs an externally enforced60-second process lifetime, one worker,256MiB memory and finite transport/input limits, a reviewed source adapter and a signing-key/rotation policy. The cooperative code deadline is not a server-owned hard kill. The proposed first normalized input cohort must be small enough for8MiB decoded/encoded and no more than eight regions. RTOFS's observed155MB full source is outside that acquisition envelope and must remain unavailable until a genuine bounded subset or separately reviewed server conversion exists. Actual CMEMS `utide/vtide` masks, returned time axis and coordinate basis must be proved before use; the outstanding licence/redistribution review remains required.

The external `thalassa-ocean-data` pipeline must retain its current13-frame display output unchanged. A later reviewed adapter can call this local API for an explicit finite region inventory, stage to a new generation, verify every object with the app decoder, and publish immutable assets before signed region pointers. The application rejects mixed/missing generations rather than using a partial cohort. Its fixed10-degree release partitions bound inventories; no global implicit fetch or provider fallback is introduced. Actual external-repository integration, manifest publication/CAS/retention, fixed proxy routes, live object verification and Safari/device signing verification remain pending.

Nine generated tests cover exact app signature/THCS round-trip, coast masks and source clocks, deterministic content generations, stale/unverified input rejection, regional/asset caps, normalized RTOFS cadence and tide refusal, immutable staging/readback, byte-accounting tampering and interrupted/cancelled staging. No real boat, licensed chart, provider forecast or production key is used. Full composed app/compiler/bundle and physical-device proof remain separate pending checks.

`providerWindow.ts` is the upstream pure normalization seam for an already acquired bounded window. Its fifteen generated tests verify actual CF timestamps, geographic scan reversal, provider component identities and missing-cell masks before calling the shared series validator. It rejects native curvilinear RTOFS rather than manufacturing a geographic grid. There is still no provider transport or command-line pipeline runner. See `docs/build138-currents.md` for primary-source facts, the conditional RTOFS rotation inference and remaining provider/licensing/operational holds.
