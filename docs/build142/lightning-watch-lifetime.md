# Held lightning watch lifecycle repair

This source fixes three independently reviewed boundaries in the held build142 watch. It does not enable a licence, provider read, production function, cron job, user opt-in, push or hardware.

Configuration, work and claim first admit the current unarchived/unreleased boat row, then try the existing owner account authority without waiting. Configuration and claim use `FOR SHARE NOWAIT`; work skips locked boat/profile rows. A busy owner account cannot be waited on while retaining a boat lock. This removes the new watch's reverse edge against actual presence/comfort boat retirement and account deletion. Profile/attempt waits remain bounded to two seconds. Their final actual time is captured after those waits.

The final clock drives readiness, entitlement,120-second original position admission,60-second work lease, five-minute original pulse admission, cooldowns and expiry. Both queue/delivery creation clocks are explicit actual admission clocks; transaction-start `now()` cannot make a delayed queue appear newly created. If queue admission itself outlasts expiry, the transaction raises and rolls back its insert. Existing caps remain: at most32 candidates/eight work leases, two-minute poll reservations,20 NM radius,15-minute cooldown, six notices/boat/day and eight/owner/day. The paid reader's global request budget is unchanged.

A durable `aa_lightning_watch_boat_retirement` fence runs before the canonical `account_deletion_write_fence` and the existing `AFTER` retirement hooks. Every boat update/delete first obtains sorted owner authority without waiting, including metadata/no-op updates; genuine contention refuses with SQLSTATE40001 before the inherited blocking fence. Only owner/archive/release changes and deletion retire attempts, disable consent and rotate the revision. Ordinary metadata/no-op updates retain the original revision and history. Archive/unarchive, release/undo and owner A/B/A do not revive prior work or deliveries. Historical deliveries retain their source dates and quota/deduplication records. The original account fence still rejects tombstoned boat updates; actual deletion retires the watch without attempting a fenced profile update. No original account-deletion or presence/comfort function is modified.

The worker also checks cancellation after awaited work/current reads, so an uncooperative late result cannot begin a paid reservation/read. Current authority is still rechecked by the atomic claim and before each actual sender HTTP attempt. Read checks cannot transaction-lock an external network send; no stronger revocation guarantee is claimed.
