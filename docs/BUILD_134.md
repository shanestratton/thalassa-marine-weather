## Existing weather server and deployed weather contracts

The `wx` GFS wind omission, changed Queensland buoy height header and empty point-forecast publication have been repaired. The scheduled publisher writes versioned `wx2:` forecast records with actual source run times, null unsupported fields and bounded cell/batch work. The 134 adapter validates this contract and aligns marine samples by UTC time. Older app builds do not consume the new publication format. This is not a complete paid-provider replacement: the server does not yet ingest the required ECMWF 9 km and regional domains. No paid subscription has been cancelled.

Production `proxy-openmeteo` v19 accepts the four exact global comparison model IDs. Live probes covered six ocean regions and all requested wind/direction/gust hours. Production `get-weather` v39 serves the compact v2 contract; full and compact responses were checked in six regions, including actual decoding by the application contract. These deployments establish backend response behavior, not release of this client candidate. Credentials remain on their existing servers and are absent from replay reports and Git.

The production checkpoint after merging the inherited 133 corrections used 10,628,998 JavaScript bytes against the unchanged 10,643,046-byte limit (14,048 bytes of room). Full app TypeScript compilation, all five source mirrors, 126 source release contracts and 188 focused merge regressions passed. Native build numbers are 134 in all four configurations; the marketing version stays 1.2.0. Fresh full hosted validation, the guarded virtual-Mac upload and Apple's processing/beta assignment must be recorded separately before claiming build 134 is available.
