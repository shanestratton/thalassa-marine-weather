# Radar target foundation (137-02)

This checkpoint adds the shared read-only TTM/TLL parser and original-clock geometry/motion qualification. Gateway/Pi ingestion, radar drawing, collision contact-key migration and AIS association are subsequent integration work. No radar control, image API, installation or relay deployment is included here.

The reviewed protocol evidence is the manufacturer-published [Navico Argus serial interface](https://softwaredownloads.navico.com/Simrad/SimradYachting_Software%20-%20Copy/Downloads/Radar/ArgusRadar_ISM_EN_988-10187-005_w.pdf), [Furuno FR10/12 interface](https://furuno.it/docs/OPERATOR_MANUAL/OME36870B_FR10_12.pdf) and [Furuno 1815 interface](https://www.furuno.it/docs/OPERATOR_MANUAL/M1815_OME-E1.pdf). These describe target identifiers, units, orientation flags, tracking/acquisition/loss, optional UTC and unavailable fields. The implementation is generic and does not assume which radar is installed.

`utils/radarTarget.ts` imports nothing and is mirrored byte-for-byte into the Pi by `pi-cache/scripts/sync-radar-target.mjs`. It requires a valid checksum for both sentence families, bounded ASCII/fields/identities, explicit measurement units and valid coordinates. Target keys remain in the radar family and never masquerade as AIS MMSIs. The controller must derive the opaque feed identity from the verified vessel and approved physical input/session. Two indistinguishable radars multiplexed with the same talker/target identifiers require separate input identities; the sentence itself cannot prove physical identity.

UTC observations are dated against the original ingress clock with midnight handling and a 15-second bound. When the sentence omits UTC, the original ingress timestamp is retained and labelled as such; polling does not restamp it. Relative position requires fresh same-feed ownship position and true heading. True bearings do not borrow magnetic heading or COG. Position and motion dependencies must be within six seconds of the observation and still within their 15-second limit.

TLL provides position, not velocity. TTM relative motion can become ground motion only by adding a qualified same-feed ownship ground vector and rotating with true heading. The earliest dependency clock is retained. Independently reported zero vectors need no invented course. True-oriented TTM speed does not itself prove ground rather than water stabilization, so it remains motion-unknown for CPA. The radar's reported CPA/TCPA are not substituted for the common collision rule. Acquiring, lost and reference echoes do not qualify motion, and stale readings cannot refresh it.

The foundation has generated tests for checksum/field refusal, missing values, units, midnight, original clock aging, same-feed dependency fences, antimeridian geometry and independent vector answers. The mirror has runtime parity tests in Vitest and the Pi Node test runner. No real boat positions or provider requests are used.

Checkpoint proof: 52 Vitest cases and the actual Pi Node/tsx test pass; strict scoped TypeScript for source, mirror and tests passes, and scoped ESLint/Prettier are clean. Whole-app compilation and actual radar feed/display/alarm integration are not claimed by this foundation checkpoint.

## Bounded input accumulator

`RadarFeed` in `utils/radarFeed.ts` holds at most 200 scoped target identities and two independent observations per identity (TTM and TLL). RMC/GGA/GLL/VTG/HDT/THS input is checksum-verified; invalid/manual/simulator navigation, inconsistent units and magnetic-only headings never supply a ground-motion solution. RMC uses its declared UTC date, and all leaf clocks are retained. Invalid-leaf watermarks prevent a delayed older valid frame from reviving a source already reported invalid.

Each radar observation captures its own exact navigation snapshot and plotted solution at ingress. Later yaw cannot rotate it. Polling returns copies, ages the original dependency clocks, and retains an explicitly aged last plotted point for at most two minutes. It cannot refresh the point, motion or active encounter. An acquiring/lost observation suppresses older tracking evidence; a return to tracking needs advancing observation time. Reset retires all navigation and targets. TTM/TLL observations keep independent clocks and motion; consumers must group by `contactKey` and retain the worst valid assessment rather than treating them as two vessels or borrowing a TTM velocity for a different TLL observation.

The accumulator checkpoint passes 64 combined Vitest cases and two actual Pi Node tests, including yaw-after-report, mutation isolation, bounded identity churn, independent TTM/TLL evidence, loss/reacquisition, bad navigation, staleness and source reset. Transport and UI wiring remain subsequent work.

## Prepared Pi controller and route factory

The Pi-only `RadarWatch` module is RAM-only and defaults off. It requires both the existing AIS watch armed state and a separate deliberate radar command. It never adopts persisted AIS state as radar consent. One enrolled controller/configuration owns each watch epoch. A replacement controller or preference change needs explicit review and exact expected-context CAS. Other currently enrolled owned devices may acknowledge the exact current alarm identity; they cannot silently take over or stand down that controller. A source disconnect preserves unresolved encounters. A confirmed owner, source-context, enrollment or AIS-arm retirement ends this radar context only. A temporary unreadable enrollment withholds public proof while retaining the private latch for revalidation.
