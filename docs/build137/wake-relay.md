## Fixed authenticated family

The existing `pi-alarm-relay` credential authentication and 8 KiB body reader run before the optional `family: 'wake'` handler. Relay owner and identity come from that authenticated door. The new family cannot supply destinations, arbitrary Signal K paths, message text, units, coordinates or queue row IDs. It admits exactly eight curated preset kinds: depth, true wind, speed over ground, measured pressure fall, coolant temperature, oil pressure, RPM and battery voltage. AIS and underway parsers, acknowledgements and budgets retain their existing contracts.

The fixed context carries the keeper's six-field owner/Pi/pair/device/enrollment/feed binding, canonical rules digest, configuration revision and process instance. Exactly eight descriptors pin enabled state, physical source hash, threshold and explicit quiet-hours policy. Quiet hours have a fixed UTC offset with integer minute bounds; no server or boat time zone is guessed. The current source's original measurement clock is required. Depth retains its measured reference or the explicit conservative full-draft allowance.

An episode key is derived by the exported `wakeRelayAlarmKey` helper from the exact context, kind, source hash and original raise time. The SQL equivalent has a behavior proof against keys generated by this helper. Unknown/stale readings cannot create, clear or re-date an alarm. Unknown evaluation invalidates pending delivery without claiming the underlying condition cleared. A resolved episode cannot be reopened by a delayed packet.

## Actions and compare-and-swap

- `probe` returns capability, bounded registered-device count and current context/revision/retirement state. An unavailable schema or delivery half reports disabled, never attempted readiness.
- `bind` sends the complete context and `expectedContextRevision` (initially `null`). Lost-response retry of an identical current profile is idempotent. Competing or delayed replacement receives reviewable HTTP 409 and must not automatically overwrite.
- `sync` sends the exact context/revision, original evaluation time, all eight states and an optional higher-priority suppression (`none`, `anchor`, `collision`, `distress`). It returns only a bounded acknowledgement-key list and queued count.
- `retire` requires the exact current context/revision and creates a new durable tombstone revision. A delayed sync, bind or retire cannot overtake it.

The Pi bridge must reconcile capability and context before sending, retain the returned cloud revision, and invalidate that binding whenever keeper owner/pair/feed/digest/configuration/instance changes. It must never automatically adopt a conflicting cloud profile. The descriptor source hash and alarm source hash must be identical. Acknowledgements must be applied only to the matching wake family, context and episode; they cannot affect AIS/underway state.

The service-only `pi_wake_apply` RPC rechecks the authoritative relay owner/enabled row and uses a short owner-scoped advisory transaction lock. Context changes are CAS operations. Context/event tables have RLS and owner-only reads, with no authenticated direct writes. Authenticated acknowledgement passes through a narrow private security-definer function checking `auth.uid()`; anonymous use and acknowledgement of another owner's event are refused.

Wake has separate queue budgets: four new pushes and two resends per owner per hour **for each of depth and the remaining presets**, at least ten minutes between resends, and at most three pushes per episode. Depth wins within a batch. Current anchor, collision/distress and depth priority are rechecked in the database without altering their leases, rows or budgets. Configuration replacement/retirement only retires its own wake rows and queue entries. The RPC has a two-second lock timeout and no network work inside the transaction.

`pi_wake_delivery_current` is checked before every APNs attempt, not just queue insertion. It refuses replacement, retirement, acknowledgement, clear, unknown source, stale original clock, quiet hours and higher priority. Quiet policy is computed at delivery time, so a retry cannot cross into quiet hours merely because the last Pi flag was false. Notification words are generated by one fixed SQL formatter. Wake is Time Sensitive only, uses its own thread/collapse identity, and sets APNs expiration to zero. A notification already accepted by APNs cannot be recalled; network/device delivery is not guaranteed.
