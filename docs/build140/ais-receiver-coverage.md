The wire and worker core require a separate current Pi consent revision, exact owner/vessel/relay/Pi/controller/enrollment/source binding, fresh P-256 signed payload, actual enabled scoped relay and atomic SQL admission. The Pi uses its existing pairing identity; it never receives a service-role key or user session. Consent acknowledgements are HMAC-bound to the existing scoped relay credential. Pairing is the existing first-use trust decision, not hardware attestation or proof that three owners are three different people. The Pi-side enrolled controller and current source checks, phone review and real HTTP mount remain separate implementation work at this checkpoint.

`20261017011825_ais_receiver_coverage.sql` keeps one private current coarse cell per receiver/vessel, one current consent, and at most16 boot replay positions per consent. New consents are capped4096, with a shared row lock preventing capacity races. No traffic or receiver position history is stored here. Batch admission costs four writes against the existing persisted hourly/daily AIS budget before changing private replay or coverage state; subsequent shared-vessel writes still use the existing bounded writer. Disabled, transferred, archived, revoked, expired or superseded policy cannot admit a batch. Withdrawal works even while fleet rights/control are held and erases that receiver's coarse cell and replay rows.

Coverage comes only from a freshly decoded actual AIVDM observation together with a separately fresh measured receiver fix reduced aboard to a fixed2° cell. AIVDO alone, provider poll receipts and an ownship GPS fix never qualify as receiver evidence. A cell needs at least three distinct current owner accounts and Pi IDs; its receiver observations must remain in that cell for five minutes before first publication. A move or observation lapse restarts that delay. Last original observations expire after ten minutes. This is coarse recent listening evidence, not a live receiver location or a promise that a target will be received.

The authenticated read RPC returns at most256 cell IDs, a global rounded/delayed `asOf`, short response expiry and explicit partial/held state. It returns no receiver identities, contributor count, exact coordinates or per-cell timestamps. PostGIS checks the actual fixed cell boxes, including dateline windows. Both new controls default OFF and separately require reviewed transport/display references; no rights are inferred from a configured provider key.
