# Local preload metadata

The configured 140 candidate `a62a72882df2fd4c0064ca9cc3b5187fc84c127f` exceeded the unchanged JavaScript limit by 84,617 bytes. Its generated Vite helpers repeated 4,250 asset paths across 151 chunks. This change moves profitable **local arrays** into inert HTML records. Every original local index, path order, JavaScript entry and CSS entry stays intact. Small arrays remain verbatim. No product feature or budget guard is removed.

The normal Vite source transform retains a small `readPreloadData` import by wrapping its existing preload marker in an identity call. Rollup owns that import before hashing, and Vite emits its ordinary parallel modulepreload. The final Vite helper reads only its own record on first use and retains its original `m.f` cache. There is no whole-table startup parse, added JSON request, eval, compressed format or change to the existing packed UI decoder/owners.

Vite replaces unused markers with `void 0` when Rollup collapses a dynamic import into its already-loaded chunk. That genuine absent-list value and ordinary arrays pass through unchanged only when no compiled record metadata is supplied. Null, objects and other values still refuse. The first configured-artifact replay exposed this case; its failed startup evidence is retained separately. A small real production build now executes that collapsed import in Node with the actual emitted reader, in addition to the complete browser replay.

Each record key hashes the exact original local array **and its own chunk filename**. Unrelated arrays cannot change its indices or key. The LF-normalized plugin implementation hash also contributes to affected chunk hashes, so a post-generation policy change cannot reuse an old immutable asset URL. The reader remains an ordinary hashed dependency: reader changes change its importers' filenames. Three small actual Vite/Terser builds verify that every common filename has identical bytes after an unrelated entry changes, and that reader edits invalidate importer filenames. The first helper line remains unmapped; all mapped body code is preserved.

The plugin accepts only the pinned Vite helper grammar, static admitted indices and the normal reader import. It rejects unknown helper syntax, escaped helpers, mapped helper prefixes, unsupported document entries and worker/router readers. Records go only into HTML entries whose actual static/dynamic graph reaches the corresponding chunks. The independent worker fence rejects this reader as well as the existing packed-data reader. Public `sw.js`, route-worker code and existing inert owner/decoder controls are unchanged.

Bounds: 256 records and 524,288 source characters per build; each local array has at most 1,024 entries / 32,768 characters, with individual flat `assets/*.js` or `assets/*.css` paths at most 160 characters. The runtime requires one inline JSON script with the compiled length, count and Adler checksum, validates every path, then removes that node and freezes the array. Missing, duplicated, external, stale or corrupt records produce the existing style of independent 44px Reload fallback without erasing mounted UI. These checks detect bundle corruption; they do not confer navigation, routing or authentication authority.

Source proof includes native JSON/DOM refusal cases, three-version immutable-cache/source-map builds, actual worker and bare-JS refusals, existing packed-data/worker purity suites, and separate Chrome/WebKit mini proofs. The browser proof covers lazy JS/CSS order, repeated use after node removal, same-length corruption with a visible Reload control, and offline replay through the unchanged real service worker. Those are synthetic source/runtime checks; the configured whole-app artifact, final byte measurement and release jobs must pass separately before adoption.

Primary references: [Rollup hook ordering and hashing](https://rollupjs.org/plugin-development/), [Vite modulepreload behavior](https://vite.dev/config/build-options#build-modulepreload). No preload dependency is filtered out.
