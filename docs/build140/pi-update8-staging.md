# Pi update8 staging controls

Preparation only. These controls do not install anything, contact a Pi, start a watch or enable sharing. Final source140, its matching server capabilities, and the safe pi5 dry run are still required before an actual release bundle is staged.

The update7 installer, rollback and anchor-lease implementation is retained in separate update8 files. Historical update5/6/7 files and allowlists stay unchanged. Update8 accepts exactly four native build140 declarations and the exact fetched master commit. A stale ancestor, an unreleased descendant, a mixed native identity and a manifest claiming another master are refused before a bundle is created. The release owner must independently verify the live master/b140 refs and TestFlight proof before invoking the stager; a local remote-tracking ref alone is not authenticated release evidence.

The source archive includes tracked pi-cache files only. It requires the track-prior reader, canonical anchor zone/parser/admission/store, NOAA edition checker and its original-source/rights mirrors, and the explicit-consent fleet forwarder. The final fleet implementation and its mirrored wire helpers must be checked against this inventory when merged. No raw/decrypted chart assets, runtime cache, identity, credentials or untracked files enter the archive.

The output is source.tar.gz, manifest.json, SHA256SUMS, install.sh, rollback.sh and their reviewed Node controls. Invoking either shell without --apply prints its plan only. Applying or rolling back requires Linux root, the existing fresh loopback maintenance protocol, a held maintenance sentinel, and no running, current or unreadable persisted anchor lease. The guard is rechecked before stopping services and after restart. Unknown or stale status refuses. A failed recovery keeps the guard held. Code backups preserve .env, cache, identity, enc-charts and reference data.

Installing code does not authorize a server half. Fleet forwarding stays off until its separate owner/Pi/source consent, current receipt, fleet control and transport/display rights are admitted. Custom-area handoff still needs compatible Pi admission and actual hardware checks; the phone keeps its existing guarded behavior until then. Licensed chart rules and NOAA checks retain their own agreement/source gates. These declarations do not turn local fixtures into boat acceptance.
