# Build138 currents: staged implementation

These source checkpoints add a strict public forecast DTO, pure sampler and bounded regional loader. They do not activate a new provider feed. The released thirteen-frame CMEMS display namespace and its byte limits remain unchanged. Publisher/proxy activation is a separate follow-up checkpoint; no complete provider grid has been acquired or published for this work.

`services/weather/currentSeries.ts` validates model/run/generation/source hash, true east/north m/s basis, surface depth, actual UTC times, provider cadence, exact buffers and per-frame known masks. It caps a cohort at eight tiles, 4096 cells per tile, 121 steps and 8 MiB decoded vectors/masks. Ocean coverage is at most 120 h and tide at most 72 h. Each tile retains its original source hash; a combined cohort also identifies all selected sources. Unknown cells remain unknown; finite zero is valid. Sampling uses nonzero spatial/temporal weights, so an irrelevant masked NaN cannot corrupt an exact known endpoint. It never clamps time or space.

The offshore adapter converts the same u/v sample to speed in knots and a true bearing **toward** which the current flows. The inshore adapter keeps u/v m/s and the existing **ETA-only** contract. Coarse currents do not establish a safe channel, depth, chart datum or clearance. Later-leg environments rebase currents, waves and exclusions together, including nested legs, while preserving forecast timestamps. The Worker boundary reconstructs only the public fields; it rejects a mixed legacy snapshot and forecast.

The legacy pure THCU sampler also rejects malformed explicit time axes and avoids zero-weight NaN reads. The existing no-network routing hold remains closed. Legacy snapshots retain their existing, explicitly snapshot-only treatment.

## Provider and activation limits

The current [Copernicus product manual](https://documentation.marine.copernicus.eu/PUM/CMEMS-GLO-PUM-001-024.pdf) separates ocean `uo/vo`, tidal `utide/vtide` and Stokes components. This roadmap requires ocean plus tide, without Stokes. The exact dataset/version and returned component coverage need a bounded source proof. Attribution follows the [Copernicus guide](https://help.marine.copernicus.eu/en/articles/4444611-citing-copernicus-marine-products-and-services); the exact licence page returned403 during review, so new routing-data redistribution remains held pending terms verification.

The older [RTOFS inventory](https://www.nco.ncep.noaa.gov/pmb/products/rtofs/) describes three-hour global surface NetCDF, while [NOMADS](https://nomads.ncep.noaa.gov/) advertises HTTPS without a RTOFS spatial filter. Actual directory metadata instead has `rtofs_glo_2ds_f120_prog.nc` without `3hrly` in the filename, and hourly early forecast files followed by three-hour frames. A HEAD plus one 64 KiB range read of the 15 October f120 file confirmed a 155,520,103-byte HDF5/NetCDF source with CF-1.0 metadata; no complete forecast was downloaded. Its actual time axis, depth, missing mask, curvilinear coordinates, vector rotation and component basis still need verification before enabling it. The contract can represent a verified three-hour subset; that is not a claim that a working bounded provider subset exists.

[NOAA current predictions](https://api.tidesandcurrents.noaa.gov/api/prod/) are distinct from tide heights. Preserve station/bin/depth, flood/ebb direction and actual times; metric speeds are cm/s. Subordinate current stations provide max/slack predictions, not a continuous curve. A point station does not establish an arbitrary radius of routing coverage. NOAA station UI/coverage and model-tide activation are not complete in this first checkpoint.

## Regional loader and remaining deployment work

`currentRegionalContract.ts` defines THCS1 payloads with bounded UTF8 metadata and exact little-endian u/v/known planes, explicit EPSG:4326 and north-to-south layout. It verifies Ed25519 signatures over the exact manifest payload bytes, immutable asset hashes and source/generation/coverage identity. `currentRegionalLoader.ts` derives fixed two-degree region IDs, splits at 180 degrees and refuses more than eight tiles before any fetch. It loads serially with an 8-second whole deadline, 256 KiB metadata/2 MiB object/8 MiB total transfer ceilings and an 8 MiB decoded cohort cap. Missing regions, model, requested tide, time bracket, mismatched generation or any cap/error return no field. There is no persistent decoded regional cache or global implicit download.

Both routing seams are wired: offshore environment loading tries the regional loader before its explicitly labelled legacy snapshot, while an explicitly requested RTOFS/tide cannot silently fall back to a different source. The inshore loader retains its closed no-WAN hold. Production regional policy is also closed and the trusted public key set is empty. Successful generated signed fixtures prove the implementation path, not a deployed data capability.

Before activation: implement/review the compatible publisher and fixed namespace proxy; verify exact CMEMS/RTOFS components, coordinates, masks, licences and finite regional acquisition/retention costs; establish a real signing key/rotation policy; prove complete published assets; measure final composed application/Worker/display resident ownership and production bytes. Proposed fixed ten-degree release partitions avoid putting a worldwide fine-tile inventory into one release. Do not raise existing map-cache or app size limits to enable this feature.

The six functional suites add signed manifest/asset mutation, exact binary bounds, complete date-line cohort, total transfer cap, abort/deadline, serial ownership and no-WAN production-hold tests to the sampler/kernel/clock/privacy regressions. Fixtures are generated public data with a deterministic test-only key. Scoped ESLint and formatting pass. Whole app/native compilation, configured production size and real regional asset proof are pending composition.

## Offline publisher checkpoint

The new `tools/currents138/regionalPublisher.ts` stages a finite signed generation from already normalized public inputs. It reuses the actual app contract and preserves original source/time/mask identity, with deterministic content generations,8MiB decoded/output caps and immutable asset readback before manifests. It has no provider acquisition or upload and leaves all production holds unchanged. Its nine generated tests pass against the real app verifier/decoder, including partial-stage failure and cancellation. See `tools/currents138/README.md` for the exact external-pipeline, resource-controller, licensing, provider-basis, key-rotation and publication work that remains. This checkpoint does not complete138-01/02 or claim operational CMEMS tide/RTOFS availability.
