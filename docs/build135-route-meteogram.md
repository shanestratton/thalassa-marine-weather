# Build 135-09: route weather

Route report → **Route meteogram** opens an hourly view along the whole traced polyline, with a scrubber and expandable table. The source, run time when supplied, received UTC, coverage gaps, TWA, point of sail and the selected `routingPolar` speed appear together. The PDF prints the same sampled rows, repeats column headers, and numbers every page.

`TracePoint` contains geometry rather than engine arrival timestamps. The view therefore requires a stated constant planned speed and labels that assumption. It never defaults a missing speed to 6 kt, derives motoring from SOG, or feeds a polar speed back into its clock. Wind angle uses the planned course, without a current/leeway correction. Every segment contributes distance and timing; spherical interpolation crosses the dateline correctly and retains the exact final position/time.

The preview is bounded to the first 384 hourly offsets plus actual arrival. A longer passage explicitly labels the skipped middle. Import a covering GRIB for large routes; a direct forecast download refuses more than 48 unique public quarter-degree cells. Forecast response units and absolute UTC brackets must be valid; a missing hour, missing cell or uncovered endpoint stays unknown. No display forecast fills a gap.

**Use weather aboard** reads the active imported GRIB first, including pressure-only files, or the loaded sustained-wind grid. It makes no provider request and never treats a gust field as sustained wind. A selected import is not blended with another source. The separate **Download selected forecast** action pins one named model, batches deduplicated 0.25° public cells through the existing proxy, caps the horizon at 16 days and the await at 20 s, and is blocked by Satellite Mode. A source run not supplied by the point API is labelled unknown, rather than replaced with receipt time.

Precise planned positions, sample rows and identity remain in memory. Geometry, account, source and configured performance changes invalidate work; cancellation and a deadline suppress late native responses even if AbortSignal is ignored. PDF/GPX share-module loading is fenced again before export. The default “now” departure is frozen to the actual sampled clock in the PDF. No chart-depth geometry or licensed chart facts are added to storage, provider requests or the PDF; the existing chart-fact privacy gate remains in place. Polar performance outside its published wind range stays unknown rather than clamping to an endpoint.

Checks: `RouteMeteogram`, `RouteMeteogramWeather`, `RouteMeteogramView`, `TraceReportWeatherExport`, `TraceReportModal`, `routeReportWeather` and `routeReportPdf` Vitest suites; `route-meteogram-layout.spec.ts` is included by the standard keyboard Playwright configuration. Its fictional, network-disabled fixture exercises the real report → local sampler → generated PDF path at 300/375 px in Chromium and WebKit. The generated three-page PDF is rendered for visual QA. No boat position or provider request is used by these checks.
