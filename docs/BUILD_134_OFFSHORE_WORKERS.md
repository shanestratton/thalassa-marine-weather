# Build 134: offshore model comparison

`compareOffshoreModels` prepares at most four independent model candidates: ECMWF IFS (`ecmwf_ifs`), GFS global (`gfs_global`), ICON global (`dwd_icon`), and GEM global (`gem_global`). UKV is excluded from offshore routing. A confirmed commercial capability enables attempts; it does not imply that any source will answer. Each displayed result requires finite, positive model wind at the route endpoints for the departure time and complete wind coverage on its modeled line. Calm, missing, expired, or unavailable input does not become a successful model label.

A model is available only when the configured proxy accepts its exact global domain and returns a finite forecast for the departure. A deployment or account capability gap remains unavailable; the client does not substitute a seamless or regional domain.

At most two disposable Workers run at once, with one 60-second budget covering model loading, worker startup, compute, and completion. A stopped or superseded request terminates its Workers. A failed worker never invokes heavy routing on the page and never replaces an existing verified route. Public forecast grids may be reused for 30 minutes, with a maximum of four entries and 32 MiB in the comparison memo.

The worker uses the existing route-engine script URL in a separate instance for each model. The offshore algorithm is extracted without algorithm changes into `isochrone/offshoreKernel.ts`. The main-thread wrapper retains its existing GEBCO HTTP fallback and progress event. The offshore Worker receives a required public relief grid and has no network fallback. Main-thread and Worker comfort retries share `runComfortAttempts`: strict, then at most +15% and +30% wave limits within the configured ceiling and time budget. Wind and gust limits do not relax.

`prepareOffshoreJob` reconstructs only position, polar, public weather, public GEBCO relief, and supported numeric configuration fields. Unknown properties, chart layers, chart identifiers, cyclone display polygons, and functions are omitted. Missing wave values remain NaN through structured clone. Current, wave, and cyclone snapshots retain their original samples; no resampling is used to reduce the payload. Forecast reference time is aligned with departure, and sampling outside coverage returns unknown. Final line samples also check actual gust values when available; absent gusts remain null and cannot pass a configured gust cap.

Every worker result is `unverified-public-data`. Its line adapter sets `selectable: false`. The passage banner's explicit comparison button opens four model rows and dashed reference lines; the inherited automatic second-model computation on the page has been removed. Selecting a candidate runs the planner's common chart/land verifier with the actual terminal legs, privately stages the hazard report, and resamples the exact checked path against its model clock, actual wind/gust and environmental limits. Only `verified-final-geometry` can update the existing passage, waypoint, save/share/export and PassageStore path. A failed, cancelled or superseded selection leaves the previous passage and its hazard report intact. A changed checked path uses the established cruising-speed clock and marks its propulsion statistics unknown. ETA spread requires at least two successful model candidates and describes forecast disagreement, not navigation clearance or calibrated route confidence.

Comparison preparation shares the same 60-second deadline as model loading and compute. Final user-requested chart validation has its own 15-second limit. Cancelling also aborts active weather requests and stops queued coordinate batches. All retained comparison grids together are capped at 32 MiB. Identity, passage, map and vessel/comfort/polar setting changes invalidate candidates. Comparison currently supports a single offshore leg; VIA passages and Satellite Mode show a specific unavailable reason instead of silently omitting waypoints or downloading forecasts.
