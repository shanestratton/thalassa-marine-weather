# Build 134: saved relief (134-08)

The Obs download button now opens **Offline Relief**. It snapshots the visible bounds, estimates the file count and size before starting, offers maximum detail 4–13, reports saved/missing/failed files, supports cancellation and deletes saved relief. Mapbox imagery/place labels and public OSM are explicitly excluded. Free NOAA/imported public charts stay in their existing Chart Locker workflow; licensed charts still require the boat Pi and are never written by this feature. Satellite Mode blocks these bulk downloads.

The plan accepts only `https://tiles.thalassatiles.com/vN/relief-{global,au}/{dem,idx}/z/x/y.{webp,png}`. Global zooms are 0–9; Australian zooms are 8–13 and restricted to the existing GBR rectangle (142–156.5°E, 29.5–9°S). There is no new high-resolution coverage outside Queensland. The base is the same `RELIEF_TILE_BASE` used by the renderer. Foreign hosts, credentials, query strings, wrong formats, unbounded coordinates and degenerate areas fail closed. Antimeridian intervals are merged before counting, including the common z0 tile. A world-sized request is counted arithmetically rather than allocated.

Each file is at most 256 KiB, with status/MIME, image signature, 256px dimensions and WebP RIFF length checks. Fetches refuse redirects and omit browser credentials. Native uses CapacitorHttp's implemented no-redirect delegate; browser uses `redirect: 'error'`. Two transfers run at once with an 18s deadline. A late native reply after cancellation cannot write a file. 404s are reported separately because relief intentionally omits all-land/uncovered terrain.

Native files live in `Directory.Data/thalassa-offline-relief-v1`, with a bounded index of safe tile URLs, sizes and usage times. A fresh process obtains the current directory URI and checks the index against real files before publishing synchronous `transformRequest` replacements. Browser saves use `thalassa-v195-tiles`, matching the production worker. Both are bounded by 4,096 files and 128 MiB of saved terrain; least recently viewed/saved terrain is evicted first. Files from the current requested area are pinned during that download: if that area itself exceeds 128 MiB, remaining files fail with a request for a smaller area rather than silently evicting earlier files from the same area. Failed index writes do not produce a saved-tile claim. Deletion reserves the operation before hydration, so another download cannot refill files while they are being removed. Partial native writes or failed orphan cleanup stop further allocation until the next successful reconciliation. Valid existing terrain remains readable and deletable when a full disk prevents a metadata rewrite. Deletion touches only this feature's validated terrain.

An offline Obs launch uses an inline background rather than waiting for a Mapbox style request. On boat Wi-Fi, `navigator.onLine` can remain true without WAN: when saved terrain exists, startup resolves the same normal initial style in RAM with a four-second deadline, then constructs with its JSON or the inline fallback. This performs no Mapbox persistence or style reset. A cancelled/stale startup cannot construct a map later. `addReliefBase` can install terrain without the Mapbox composite source. Hydration/download/delete refresh only the four relief sources through public `setTiles`; they never replace the style or access private `_reload` internals. Pending/failed remote tiles do not prevent a local-source refresh. Existing chart layers survive. The normal map palette and provider/derived-data credits remain present. Browser site-data deletion still removes browser saves; native filesystem restoration is independent of the service worker.

## Evidence

- Live read-only checks on 16 October 2026: v1 global z0 PNG and WebP returned HTTP 200, correct MIME and 256px headers (27,247 / 60,644 bytes). An Origin-bearing request returned `Access-Control-Allow-Origin: *`. No server settings were changed.
- Ten focused Vitest suites: **141 tests passed**, including old public OSM bulk-disable and viewed-cache lifecycle tests. New cases exercise actual planner bounds/counting, strict paths, image/MIME/stream limits, native cold-module hydration, size/LRU enforcement, failed and partial writes, orphan-cleanup failure/retry, browser eviction, full-disk read/delete recovery, deletion/download races, late-response cancellation, modal controls, synchronous map interception, boat-LAN style failure/deadline, cancelled chart startup and service-worker cache precedence.
- Actual Chromium and WebKit: **2 cold-start rendering tests passed**. A real downloader saves synthetic decodable terrain; the ordinary viewing cache is removed; the app page closes; a fresh page restores the saved index and real Mapbox draws depth pixels with credits from the saved cache. Every saved URL is served locally. All worker network fallback is forced to reject; no production data or account is used.
- Chromium additionally uses `context.setOffline(true)`. WebKit instead stops the loopback origin and rejects worker fetches because [Playwright issue 42775](https://github.com/microsoft/playwright/issues/42775) causes its offline emulation to reject even literal service-worker responses. The test records the method, saved counts, pixel values and rejected requests. Nothing is skipped.

These are browser and mocked native-storage results, not a physical iPhone persistence claim. Airplane-mode app relaunch on an installed build remains a device acceptance check. No production service, database, licensed chart storage or chart entitlement changed.
