# Exact relief row representation

The production-only plugin replaces the literal row representation of the two reviewed AU250/NZ v2 availability inventories. The source JSON, metadata, tile coverage, ordering, numeric values, caller exports and admission limits remain unchanged. SHA-256 pins require a fresh review for any source change; CRLF/LF checkout normalization is allowed. Other JSON, raw/URL assets, development and worker builds retain their existing path.

Rows are restored from counted JavaScript through the existing pure bounded `decodeClassNames` helper, then split into the original four integer fields. No HTML table, DOM reader, eval, new dependency, decoder ceiling, post-hash chunk mutation or worker policy change is introduced. Vite hashes the final transformed module normally. Default and named exports retain their shared ordinary mutable row array, matching Vite's original JSON output.

The exact isolated production minification of both original JSON imports is26,070 bytes; the packed version is16,518 bytes including the complete existing decoder and inflate primitive:9,552 bytes saved. A whole-app saving cannot be inferred exactly from that isolated graph because the decoder is already shared in the application. The whole configured build and unchanged total-JS/asset caps remain required after composition.

Proof:44 cases across five suites pass, including all626 AU rows and724 NZ rows with bit-exact numeric/order checks, actual minified default/named export equality, deterministic encoding, corrupt/bomb/bounds refusals, original raw/URL asset handling and an actual isolated Vite worker build with no packing or DOM reader. Existing regional availability, activation, contour and region-boundary tests pass unchanged. External evidence is `work/validation141-relief-packing-focused.log` and `work/relief141-isolated-actual-measurement.json`.
