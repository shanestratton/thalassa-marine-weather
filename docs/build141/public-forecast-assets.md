# Public forecast release reader

The build141 scalar and observed-SSH consumers use the fixed existing-project `forecast-assets` function. It serves only `gfs-atmos`, `ifs-pressure` and `ssh` from the public `shanestratton/thalassa-ocean-data` GitHub releases. No private dashboard, weather provider, paid API, user coordinate or caller-selected URL is involved.

`GET /functions/v1/forecast-assets/<dataset>/manifest-v2.json` and the original generation-qualified `g-…-hNNN.bin` filenames are the complete admitted API. The local function-server prefix is also accepted. All query parameters, alternate datasets, slot filenames, legacy aliases, mutations and partial requests are refused. Preflight is credential-free; a valid data read always consumes the same public quota, even if a caller supplies an Authorization header. No caller credentials, cookies or IP headers are forwarded to GitHub.

The existing shared HMAC quota calls the existing service-only `consume_public_edge_quota` RPC with the static `forecast_assets_public` bucket and 120 requests/hour/client. Missing server configuration/address, a denied or failed RPC, cancellation or the eight-second quota deadline holds the read before GitHub access. The shared helper's new optional signal is used only here; existing authenticated/public callers retain their original behavior. Raw client addresses are not stored by the quota RPC. The function remains publicly readable and does not grant database or user-data access.

The executable shared proxy remains the original transport: two independently bounded discovery slots, full scientific/identity/currentness admission, exact public repository/tags, manual redirects to the existing two approved GitHub hosts only,20-second upstream deadline, abort-raced body reads, fixed per-dataset byte caps and complete-object digest/ETag headers. The server computes the delivered asset's digest; the client independently compares the bytes with the hash/size in its admitted original manifest before decoding. A digest header alone does not make a binary a qualified forecast. Atmosphere and SSH source clocks, masks, source lifetimes, owned rendering and two-frame atmosphere bounds are unchanged. The legacy seven datasets keep their original contracts and Node emergency-bridge environment behavior; a missing Node process global fails that bridge closed in Deno.

Only `AtmosSession` and `sshObservations` move to this function URL. `API_BASE`, other consumers, CSP, dependencies and product enablement flags are unchanged. The current CSP already admits the existing `*.supabase.co` origin. New contract imports use explicit `.ts` paths, which both the current app TypeScript configuration and actual Deno accept. No migration is needed: read-only inspection of the live RPC confirmed its existing bounded generic bucket contract.

On 2026-10-17, read-only live inventory found 67 active Edge functions and no `forecast-assets`; adding one is below even the documented Free 100-function limit. This is an inventory observation, not an account billing-plan assertion. The current platform limits also include 256MiB memory and 2 CPU seconds/request. The largest admitted new binary is SSH 4,406,464 bytes; no new library was installed. Actual hosted CPU, quota forwarding headers and public response behavior still require the release owner's post-deployment probe before activation.

The current official [authentication-header guide](https://supabase.com/docs/guides/functions/auth-headers) requires gateway JWT verification disabled for bare public calls, so the function is explicitly in the reviewed credentialless registry with its internal quota rationale. The [function limits](https://supabase.com/docs/guides/functions/limits) informed the bounded implementation. The changelog was checked first; the relevant [CBC cipher retirement](https://supabase.com/changelog/cbc-tls-ciphers-deprecated) is compatible with the standard runtime TLS transport used here. No insecure TLS setting or network workaround is added.

Source verification includes the original proxy and session suites plus the new public admission tests. The actual Deno 2.9.4 entry registers `Deno.serve` and executes the real shared quota implementation against network-denied synthetic RPC/GitHub responses: HMAC-only database input, no user-auth bypass, quota failure/missing configuration, strict paths, redirect refusal, both discovery slots and no-Node legacy handling. The first Deno fixture's millisecond timestamp was correctly refused; its log remains, and the fixture now emits the contract's original whole-second UTC timestamps. No scientific timestamp rule was widened.

The existing Chrome/WebKit phone fixtures replay only bounded synthetic atmospheric brackets and the previously captured published SSH image, using the new URL and real CORS response semantics. Original pixels, source retirement, credits, 300/375px at 130% text and fixed page extent assertions remain. This is local replay evidence, not a deployed gateway, provider acquisition or physical iPhone claim. Final exact results and immutable input/evidence hashes are retained in the external source proof receipt.

Deployment, manifest/frame live readback, final configured bundle budget and feature enablement belong to the release owner. This source packet performs none of them.
