# Lazy imports during document navigation

The first build 139 Linux WebKit artifact run failed while the real entry test navigated from `/plan/synthetic-proof` to `/logs/no-real-vessel`. Logs was interrupted by a second navigation to the outgoing Plan URL. The original test and its deadlines remain unchanged.

The retained Ubuntu trace shows the test starting Logs while Plan's lazy imports were pending, cancelled module requests and import rejections, then another Plan document request. Its fresh browser context attempted `/plan/sw.js`, which returned `text/html`; that response could not install a service worker. The worker source has `clients.claim()` but no `client.navigate()` recovery path.

A separate Windows WebKit diagnostic reproduced the exact interruption by holding the real ForecastSheet response and delaying the Logs response by 250 ms. Observable storage writes identified `lazyRetry_default`, `lazyRetry_lastReloadAt`, and the `lazyRetry:reload` flight crumb after `beforeunload` and the cancelled import. Its existing configured artifact is older than the current source, so this is causal diagnosis, not release acceptance. Source maps independently confirm its `lazyRetry.ts` and `index.tsx` are identical to the failed release sources. The unmodified local sequence passed both engines before this controlled reproduction; that result does not invalidate the genuine Linux failure.

The fix records `beforeunload`/`pagehide` only while each rendered lazy factory is pending. A rejected attempt that observed document retirement rethrows its original error without reloading or arming either cooldown key. Both listeners are removed when the factory resolves, rejects or throws synchronously. Calling `lazyRetry()` itself remains side-effect free. Stationary stale-chunk recovery, per-module retry, and the existing 60-second global cooldown are retained. A navigation attempt conservatively retires that pending attempt even if a browser subsequently cancels navigation; it may surface its error normally, and never forces the outgoing URL over the user's chosen destination.

The focused tests exercise actual React lazy rendering: both teardown events, rejection propagation, successful/synchronous cleanup, ordinary stale recovery and both original fences. The existing purity/parked-page suite is retained. The artifact browser suite adds the real pending-ForecastSheet/provisional-Logs sequence and checks the destination, no extra Plan navigation, exact display-data consumption and untouched recovery keys. It neither mocks application context nor replaces the original entry test with a fresh Page.

External evidence is preserved under `work/release139-navigation-failure-trace`, `work/release139-outgoing-navigation-diagnostic-ready`, and `work/release139-outgoing-navigation-controlled-abort`. The initial diagnostic server-readiness refusal and original Linux artifact remain separate. Exact final production-artifact browser and full release CI proof are required after source composition; unit/diagnostic results alone are not release acceptance.
