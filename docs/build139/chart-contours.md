# Build139-10: chart contour display preferences

The existing **Charts & detail** sheet now offers shallow, safety and deep depths, an explicit Apply action, Reset, and an optional Relief safety marker. Depth inputs follow the account's metre/foot unit. Unchanged foot fields retain their exact stored metre values rather than rounding the vessel's choice on every save. The existing account settings store persists the small optional `chartContours` preference; the new editor rejects late actions from another account. Reset emits explicit JSON null, which survives the existing cloud object merge, instead of an omitted undefined property that could resurrect an older choice.

There is no extra interactive map-menu row. When enabled on a Relief base, its existing menu footer says **Relief safety marker ~X m · not for navigation**. The chart key explains the approximate model marker. No MSL or chart-datum equivalence is inferred from blended model pixels.

## Display boundaries

- Inputs must be finite and strictly ordered: `0.1 <= shallow < safety < deep <= 6000` metres. Corrupt/absent settings retain the existing chart bands. A valid choice raises the displayed safety contour to at least the existing vessel draft-plus-margin floor; if necessary the deep band also rises to preserve ordering. The raw account choice remains unchanged when the vessel draft changes.
- The chosen bands colour DEPARE at its chart datum and use the next available deeper actual contour **in each loaded cell**. A neighbouring cell's different interval cannot remove its bold contour or promote a shallower one. No qualifying contour means no bold contour there.
- The physical safety depth, worst-case hazard threshold, satellite glaze, route checks, clearance and alarms retain their separate existing inputs. No navigation service consumes `chartContours`, no tide provider contributes to this model, and the existing WorldTides informational-only containment remains in place. A synthetic visual-offset regression proves offsets do not move the datum-based bold contour.
- Missing and explicit JSON-null DRVAL1/VALDCO are unknown, not numeric zero. The shared numeric Mapbox expression now guards explicit null as well as missing keys; unknown depth remains transparent and unknown contour values have no numeric label. Existing case-defensive and garbage-value handling remains.
- Relief applies a client paint expression to the **already loaded** index raster. The encoder is `tools/relief/encode_tiles.py`: index 0 is land/unqualified very shallow model depth, 1–254 are logarithmically quantized model water depth, and 255 is outside that water encoding. With the marker on, 0/255 stay transparent. The warning cutoff rounds the safety index upward, retaining the coarser bin as caution; it creates no measured contour or clearance guarantee. Deeper pixels retain the existing palette, without a new safe-water colour. Day/night/palette/style reloads retain the selected marker through existing public paint APIs.

There are no new provider queries, chart uploads, raster downloads, persisted chart geometry, backend changes, R2 writes or licensed-data copies. The fixture contains invented local polygons and generated encoded raster stripes only.
