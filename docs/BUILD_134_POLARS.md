# Polar tools — 134-06

The owner can adjust sailing performance from 70–130% on the Polars page. The routing label reports an explicit adjustment. The resolver applies it after factory/learned blending, changes the route-cache signature, passes adjusted generic figures to the edge router, and preserves the adjustment in the Passage HUD without changing engine cruising speed. A missing setting keeps the previous routing behavior.

The target builder makes a clearly labelled starting estimate from beat, beam-reach and dead-run speeds at a chosen true wind speed. Other winds follow the existing generic cruising shape. It is not a measured or licensed yacht library. Replacing existing figures requires confirmation. Grid axes can be added or removed up to 30 entries each; interpolation fills interior new cells, and new extremes are empty. Existing cells retain their values. Removing a row or column requires confirmation, and pending edits still save on exit/background.

Native export uses the existing Capacitor file/share plugins and a safe cache filename. `.pol` uses [Expedition's documented wind-speed then angle/speed-pair format](https://www.expeditionmarine.com/Downloads/Documents/Expedition.pdf); `.csv` is a TWA-by-TWS table. Both are round-trip tested through the app's existing readers. A browser download is provided for web use. Actual Expedition/OpenCPN import and the iOS share sheet still need device acceptance.

Phone and Pi learning include 30°, 35° and 40° alongside the previous 45–180° rows, making 63 exported cells. Old buckets and Pi checkpoints are retained. The Pi preserves its 42-cell `polars` response for older apps and adds optional 63-cell `extendedPolars`; the new app prefers the extension. It accepts older snapshots and merges by angle/wind value, so an older Pi row cannot be assigned to a different angle. Existing engine, freshness and outlier gates remain in effect. The HUD refreshes the same paired Pi/phone blend used by the asynchronous routing resolver.

Tests cover scaling/no-go/motoring separation, interior-grid interpolation and axis limits, target anchor speeds, file formats, share cancellation/failure, edit preservation, replacement/removal confirmation, old-Pi compatibility and close-hauled learning. These are behavior checks, not evidence of faster or safer routes. The separate routing benchmark and physical sailing/engine checks remain acceptance gates. Fixtures are generic or fictional and do not hard-code an owner's boat, route or region.
