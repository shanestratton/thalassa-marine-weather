## Decision (our recommendation)

### H1. public/sw.js: Mapbox tiles in their own cache, under 29 days (cut-line item 3)

- **29 days, not 30**: a tile stored at 23:59 is never served on day 30 whatever the clocks do. "Within the rules"
  with a day's margin costs one re-download a month.
- New constants: `MAPBOX_TILE_CACHE = 'thalassa-v200-mapbox-tiles'`, `MAPBOX_MAX_AGE_MS = 29 * 86_400_000`,
  `MAPBOX_TILE_LIMIT = 800` (512 px @2x imagery is heavy; 800 bounds the store to roughly 100-200 MB), and a stamp
  header name `x-thalassa-cached-at`.
- `mapbox.com` leaves the shared tile branch and gets its own branch, ahead of it:
  1. Look only in `MAPBOX_TILE_CACHE` (never the runtime or offline caches).
  2. A hit with a stamp younger than 29 days is served. An older or unstamped hit is deleted (in `waitUntil`) and
     treated as a miss.
  3. A miss fetches from Mapbox. A 200 `image/*` response is stored as a stamped copy (`new Response(blob, {status,
     statusText, headers})` with the stamp added; content-type kept), then count-pruned every 64 writes. Other
     responses pass through unstored, as today.
  4. Network failure on a miss returns the same empty 404 as today. **An expired tile is never served, even
     offline.** (The desk is ashore; the native app never runs this worker.)
- **Housekeeping, so expired bytes do not sit on disk:** the keep-list gains `MAPBOX_TILE_CACHE`; `activate` deletes
  every `mapbox.com` entry from `RUNTIME_TILE_CACHE` (they are unstamped, so their age is unknown) and sweeps
  `MAPBOX_TILE_CACHE` for expired entries; and the first fetch after the worker starts runs the same sweep once (a
  module-level flag), so a skipper back after six weeks is cleaned on the first request.
- Tidy, same file: drop `open-meteo.com` from the network-first data branch (:713), which nothing will call after H2.
- Mapbox GL JS's own tile cache is untouched: it is Mapbox's qualified renderer managing its own content within its
  terms (§2.8.3).
- **H1-floor (if H1 is cut):** remove `isHostOrSubdomain(url.hostname, 'mapbox.com') ||` from the tile branch and
  add the same activate-time deletion of `mapbox.com` entries from the runtime cache. About 0.2 KB, compliant on the
  day; H1 proper follows in 128.

### H2. Open-Meteo: the paid endpoints, the key on the server, everywhere

a. **proxy-bosun-fallback** (edge; Shane deploys): the three URLs move to `customer-geocoding-api`,
   `customer-api` and `customer-marine-api`, each with `apikey` from `Deno.env.get('OPEN_METEO_API_KEY')`, built with
   `URLSearchParams`. No key: geocode returns null and the tools return their existing error strings; **never a free
   fallback**. No URL is ever logged or put in an error message (the key is in it); today's messages carry only the
   status (:378) and keep it that way. The docblock and Required Secrets say so.
b. **check-weather-alerts** (edge; Shane deploys): the free fallback at :176-180 goes. No key: skip the fetch and
   `console.error` once per run without the URL.
c. **Calypso's on-device geocoder** (services/voice/cloudTools.ts:24-43) goes through the boundary the app already
   uses: proxy-openmeteo gains a third fixed operation, `geocode`, upstream
   `https://customer-geocoding-api.open-meteo.com/v1/search`. Its own validator in validation.ts accepts exactly
   `name` (1-100 characters, no control characters), `count` (1-10), `language` (two lowercase letters) and
   `format` ('json'); nothing else, no coordinates. `OpenMeteoOperation` gains `'geocode'`; cloudTools calls
   `fetchOpenMeteoProxy('geocode', { name, count: 1, language: 'en', format: 'json' })`. Same quota lane, same
   no-store response.
d. **The parked public wind barbs are deleted**, not rerouted: src/windField.ts, src/components/WindBarb.tsx and the
   barb state, effect, markers and parked toggle in src/components/MapContainer.tsx. Shane removed the button on
   2026-07-19; the "stay wired" note was ours, not his. If he wants barbs back, they come back through the proxy
   (git has the drawing). This is also the package's JS trim.
e. **The CSP stops allowing the free hosts**: remove `https://api.open-meteo.com`, `https://marine-api.open-meteo.com`
   and `https://geocoding-api.open-meteo.com` from `connect-src` in index.html and vercel.json's `/(.*)` header. The
   browser then enforces the licence: any future direct call fails in development, not in an audit. (index.html's
   meta CSP also governs the iOS webview, which is why c and e land together.)
f. **The guard test grows teeth** (tests/OpenMeteoSecretBoundary.test.ts): the free-host regex becomes
   `https:\/\/(?:api|marine-api|geocoding-api)\.open-meteo\.com`; the scan adds hooks/, utils/, stores/, pages/ and
   supabase/functions/; the expected list of free-host files becomes `[]` (the exception comment goes, its reason
   gone with d). Every file under supabase/functions that names a `customer-*.open-meteo.com` host also reads
   `Deno.env.get('OPEN_METEO_API_KEY')`. The edge-shape assertion `"operation !== 'forecast' && operation !==
   'marine'"` (:84) is updated to the new three-operation allowlist, never deleted. The CSP strings contain no
   `open-meteo.com` host.

## Sceptic pass

1. **"30-day cap" read literally would serve a tile on day 30 under clock skew.** 29 days.
2. **Stamping needs the response headers**, and a CORS response exposes only safelisted ones. The stamp is our own
   header on a stored copy, so nothing depends on Mapbox exposing `Date`.
3. **Old Mapbox tiles in the runtime cache have no stamp**, so their age is unknowable; they are purged at activate,
   not grandfathered.
4. **"Expired bytes on disk" is still caching.** Swept at activate and on the first request after start; the plan
   says honestly that a browser holds them until the skipper returns.
5. **Cutting H1 must not mean cutting compliance.** H1-floor is the one-line version.
6. **"Fix proxy-bosun-fallback" alone would leave the same free geocoder running on every phone** (cloudTools) and a
   dormant one on the public page. All four go, and the CSP closes the door behind them.
7. **A new edge operation is new attack surface.** It is a fixed upstream, a four-name allowlist, the same quota lane
   and no-store responses, with deno tests, exactly like forecast and marine.
8. **The personal-port finding is bigger than anything here**, but it needs a migration and a purge; it is named for
   128 with a recommendation rather than smuggled into a build Shane asked to keep to its list.
