## Decision

1. **Two stores, by licence.** A cell is **open** only if C-b's `isOpenChartCell(cell)` says so.
   - In 127 that means a NOAA id (`^US[0-9][A-Z0-9]{5}$`, the rule at cloudCellSync.ts:93-96).
   - Everything else is **protected**: o-charts OC-*, S-63 names, unknown ids, unsigned packs.
   - The Pi index's `licence` field (C-b) can only make a cell protected, never open, in 127. Fail closed.
2. **Protected bytes live in RAM only, in a new `services/enc/boatCellVault.ts`.** The parse cache stays
   in front of it as L1.
   - **Storage.** An LRU of gzip-compressed cell text (CompressionStream). Text is held only until its
     compression finishes. Byte budget `VAULT_MAX_STORED_BYTES = 40 MiB` compressed; plain text with a
     96 MiB budget if CompressionStream is missing. At least 16 cells are always kept.
   - **API.** `put(id, text)`, `getText(id)`, `has(id)`, `drop(id)`, `clear()`, `trim(fraction)`,
     `stats()`.
   - **Sizing.** 40 MiB of gzip is a few hundred MB of cell text: a full merge window (≤ 32 MB) plus a
     route corridor plus the 20-cell prewarm, with room to spare. L1 can then evict freely, even at 16 MB
     while plotting, without forcing a Pi round trip or arming the fruitless-walk latch
     (EncHazardService.ts:1815-1866).
   - **Measuring.** `registerCensusProbe('encVault', …)` feeds the census. One `log.warn` line ("vault: N
     cells, X MB stored, Y MB text") on each Pi registration and every 50 puts. log.info is a no-op in
     production, so the device smoke needs warn.
   - **Memory warning.** The memoryGauge warning handler also clears L1 and trims the vault to half.
   - **The Roberto switch.** `BOAT_CELLS_ON_PHONE = true` is one constant. If Roberto answers Q1 "no",
     setting it false makes the registry and vault refuse protected cells, and the words say "Licensed
     charts stay on Serene Summer's Pi in this build". Routing aboard then moves to the Pi in 128 (vision
     §5).
3. **EncCellStore branches on licence. Protected cells never touch a Filesystem call.**
   - `saveCellGeoJSON`: protected → `vault.put(id, data)`, using the string it already builds today at
     :305, so there is no extra stringify. Open → disk.
   - A protected cell that reaches the disk write path throws (defence in depth; a test proves it).
   - `readCellRaw`: L1 → vault (`kind:'text'`) → open file → `missing{notFound:true}`, so the ladder and
     the hydrator run.
   - `hasCellGeoJSON`, `deleteCellGeoJSON` and `clearAllGeoJSON` cover both stores.
   - Ladder: L1 → vault → open file → Pi (any cell) → cloud (NOAA). Rung 3 goes with C-a.
4. **Open cells move out of Documents.**
   - **Native:** one new method, `prepareChartStore`, on the existing EncryptedLargeStoragePlugin. It runs
     on its private `workQueue` (:59; the bridge-queue rule) and reuses `excludeFromBackup` (:502).
     - It creates `Library/Application Support/enc-open` with data protection
       completeUntilFirstUserAuthentication and `isExcludedFromBackup = true`.
     - It returns that path relative to Library.
     - The JS store then uses `Directory.Library` + `Application Support/enc-open/<id>.geojson`.
     - No new Swift file, so no pbxproj entry and no cap-sync churn.
     - We don't rely on `LIBRARY_NO_CLOUD`: its backup flag is inside a binary we can't read.
   - **Web:** the open store stays `Directory.Data/enc-cells` (IndexedDB).
5. **One sweep per launch, cheap and idempotent. It replaces both the 127 upgrade purge and the deferred
   126-20 launch purge.** No "done" flag, so a run cut short by a kill simply finishes next launch.
   - **(a) Registry, sync, on first access to EncCellMetadata.**
     - Delete every localStorage record that is not open: o-charts, S-63, unknown ids, pending cloud
       registrations, personal-manifest cells.
     - Then clear `thalassa_enc_auto_publish`.
     - On Shane's phone this is about 1,000 `removeItem` calls and one index write: milliseconds. Later
       launches iterate only the open records.
   - **(b) Files, async, the first thing `storeReady()` does before any store call resolves.**
     - `stat` `Directory.Data/enc-cells`. If it is absent, done.
     - Native:
       - `prepareChartStore()`.
       - Confirm `getUri` of the old and new folders differ. If they don't, delete nothing: this is the
         LocalDatabase.ts:98-110 lesson, where build 102's "move" deleted the only copy.
       - `Filesystem.rename` each open record's file into enc-open. A failed rename marks that record
         `pending`, so it re-hydrates from the NOAA shelf or the Pi.
       - Then one recursive `rmdir` of the old folder. That removes every protected file and every orphan
         in a single native call (about 1 GB on Shane's phone).
     - Web: `readdir`, then `deleteFile` each non-open file and keep the open ones.
     - One `log.warn` summary with counts only ("enc store: removed N licensed, moved M open").
   - **(c) Chart pictures in WebKit's HTTP cache, once (127-C-b decision 11 owns the why).**
     - One more method on the same plugin, `purgeWebDiskCache`: `WKWebsiteDataStore.default().removeData(
       ofTypes: [WKWebsiteDataTypeDiskCache, WKWebsiteDataTypeMemoryCache], modifiedSince: .distantPast)` on
       the main queue.
     - **Never** local storage, IndexedDB, cookies or `WKWebsiteDataTypeFetchCache`. The last is Mapbox's
       own Cache API store, which holds Mapbox tiles only.
     - JS calls it once, behind `thalassa_webkit_cache_purged_v1`. The flag is set only after the call
       resolves, so a kill retries next launch.
     - The cost is one refetch of HTTP-cached weather and imagery tiles.
     - Native only. The web never fetched o-charts tiles (Pi integration is off there).
6. **The protected registry lives in memory too.**
   - `EncCellMetadata` gains a session overlay (`boatRecords: Map`):
     - `putCell` sends a protected record to the overlay and never to localStorage, keeping the kill #41
       rule: a byte-identical record writes nothing and notifies nothing (:340-356).
     - `readIdentityGroups` merges the overlay.
     - `removeCell` and `clearAllCellMetadata` clear both.
     - New: `clearBoatRecords()` and `boatRegistryLoaded()`.
   - Away from the Pi after a relaunch the registry holds no licensed cells. Every existing consumer then
     takes its honest "no chart here" path, and nothing claims coverage without bytes.
   - The persisted catalogue (ids and bboxes) also stays off disk. That gives no ashore coverage outlines
     in 127, by design (Not in this build).
7. **Registration aboard, from the Pi's index (metadata, no blobs).** `syncEncFromPi` splits the Pi's index
   up front:
   - **Protected rows** are registered in memory in one batch (suspend/flush notifications → one registry
     bump → one merge). Each record carries the row's edition, update, issued, bbox, contentSha256,
     `sizeBytes = piSizeBytes = row.sizeBytes`, and `hazardCount = row.featureCount` (refined at import).
   - **Identity rule.** For protected cells, `sizeBytes` is always the Pi's size. `importCell` keeps the
     registered record's sha and Pi size for the same revision. Registering then importing therefore leaves
     `getRegistryFingerprint` unchanged, so there is no mid-session "chart library has changed" and no
     Cast Off recheck loop (Shane, 2026-08-26). Routes checked before 127 get one honest recheck.
   - **Prewarm.** The same run then pulls the nearest `AUTO_SYNC_MAX_CELLS` (20) protected cells not
     already in the vault, as today's priority ordering does (EncImportService.ts:655-675). It skips while
     plotting.
   - **Open rows** keep today's pull-to-disk plan (planPiCellSync).
   - **The whole protected index registers in one batch, as navigation records** (so they are in
     `listCells()` and the fingerprint before any blob arrives; `pickNavigationCell` drops 'pending',
     EncCellMetadata.ts:196-205). `boatRegistryLoaded()` flips only after that batch, never part-way.
   - **Registration is metadata only, so it is never deferred by plotting.** Only the prewarm's blob pulls
     keep the `tracerActive` deferral (see 7a for why this matters).
   - **The account flag for the desk (127-DESKMAP C1).** After the batch, `registerFromPiIndex` sets
     `settings.boatCharts = { licensed: <any protected row> }` through `updateSettings`, **only when the value
     changes** (no write per launch). It is one boolean in `user_settings` (merge_user_settings has a deny-list
     only, 20260728090000_user_settings_contract.sql:125-135, so no migration). No count, id, bbox or name.
     `forgetPairing` sets it to null. Another paired device re-asserts it at its next registration.
   - **The tracer and the background check wait for this registration: decision 7a.**
   - **The manual "Sync from Pi"** does the same: register + prewarm 20, never "every cell into memory".
     The per-chart pull (cellIds) puts that one cell in the vault. "Sync N charts" counts open rows only.
7a. **The tracer's crash-loop guard and the background check wait for the boat registry (critic HIGH, passes
    2 and 3).**

    **Why (b127, read 2026-10-10):**
    - **The hydrate is one-shot.** `legCacheHydratedRef` (useTracerGrading.ts:163) gates it. It is keyed to
      the whole-library `getRegistryFingerprint()` (:226-234, routeTracer.ts:2072-2095).
    - **The bank is one payload per account, rewritten after every cluster and at the end of each pass**
      (:335, :346; `persistLegVerdicts` `setItem`, routeTracer.ts:2054-2066). A pass graded before
      registration therefore doesn't just miss the hydrate. It **overwrites the aboard bank** with a fingerprint
      that has no protected cells. The no-chart verdicts are volatile and never enter the cache (:309-322), so
      the bank becomes empty or open-only. After that, even a correct hydrate has nothing to find.
    - **Registration alone never re-runs the grading effect.** Its deps (:354-369) hold no registry term.
      Volatile legs retry only on the next pin or vessel change (:246-252).
    - **The in-memory cache outlives a registry change** ("chart data is static for the session", :209-211).
      In a window with an open cell and an unregistered protected one, scale shadowing knows only the
      registered extents (InshoreRouter.ts:4444-4449, :4479), so the coarser open chart grades the leg. A
      durable 'clear' from that window stays all session and is banked under the loaded fingerprint: a false
      clear. In all-protected water, `assembleTracerLayers` returns null (:4449, :4541) and the leg is the
      volatile "no ENC chart here" (traceGrading.ts:294-299). Release refuses that
      (traceVerification.ts:161-166), so it is honest but costs a full regrade.
    - **Registration rides the auto-sync, which never runs while the tracer is open.** The auto-sync waits
      10 s after boot (autoSyncFromPi.ts:80) and returns early while `tracerActive` (:60-64, :95-98, from
      useTracerSessionEffects.ts:89). The 10-minute poll defers the same way. Pass 2's "wait ≤ 20 s, then
      grade as not-aboard" would hit its cap at every launch with a route open in the tracer, then grade
      without the licensed cells. That is exactly what it meant to stop.
    - **The background check has the same timing problem** (traceBackgroundCheck.ts:240-247, while the Log
      page is open). Before registration it cold-rechecks routes over protected charts and records 'nochart'
      (:323-324). The memo key carries the scoped fingerprint, so once the registry lands it rechecks them
      all again, at minutes per route.

    **Design:**
    1. **`ensureBoatRegistry()` in piCellSync.ts, the first half of `ensureBoatCells` (8b).** It runs the
       steps in this order: switch, pairing, mirror, `ping()` ≤ 3 s, tailnet, the `/api/enc/installed` index,
       then `registerFromPiIndex` in one batch. It pulls no blobs.
       - Beside it: `boatRegistryState(): 'none' | 'pending' | 'loaded' | 'away'`,
         `whenBoatRegistrySettled(capMs)`, and `subscribeBoatRegistry(fn)`.
       - The subscription fires **only on state transitions**, never per `putCell` (the kill #41 lesson).
       - 'none' covers: no pairing, `PI_INTEGRATION_ENABLED` false (the web and every unpaired phone,
         piPublicBetaBoundary.ts:63, `getPairing` PiPairingService.ts:79-89), or `BOAT_CELLS_ON_PHONE`
         false.
       - 'away' covers: ping failed, tailnet, C-d's 401/403, or the cap.
    2. **The hook (useTracerGrading).**
       - `legCacheHydratedRef: boolean` becomes `hydratedForRef: string | null`, the fingerprint the last
         hydrate was tried against. That way an open-cell `putCell` mid-session costs at most one more
         localStorage read, not one per pin.
       - New dep `boatEpoch` (`useSyncExternalStore` on `subscribeBoatRegistry`). It bumps at most two or
         three times per launch. A re-run whose legs are all cache hits grades nothing (:287).
       - On mount it calls `ensureBoatRegistry()`, so the tracer waits neither for the 10 s boot deferral nor
         for the plotting deferral.
       - **'pending':** no hydrate, no grade, no persist.
         - It publishes nulls, so the rows say "checking…", with status 'loading'.
         - A new setter, `setTracerChartsWait('opening')`, lets MapHub's loading line (MapHub.tsx:4424-4428)
           read `boatChartsLine('opening', name)`: "Opening Serene Summer's charts from the Pi…".
         - Release refuses through the existing 'loading' rule (traceVerification.ts:158-160), so neither
           Save nor the auto-bank can mint anything.
         - **Cap: 20 s from the hook's first pending pass** (not from boot). After that the pass runs as
           'away' with reason 'slow'.
       - **'loaded' and 'none':** today's code, except that the hydrate runs whenever
         `getRegistryFingerprint() !== hydratedForRef`.
         - On the transition to 'loaded', it first drops every cache entry graded while not loaded
           (`provisionalKeysRef`). Then it hydrates, so the bank's entry wins. Then it grades only the legs
           still missing.
         - Volatile entries clear themselves, because the registry version moved (:246-252).
