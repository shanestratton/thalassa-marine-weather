## Decision (our recommendation)

1. **Reuse the dormant day-plan mode; do not add a second one.** Replace
   `reviewProposal` with `dayPlan?: { proposal; stopName; departureMs;
   onBack; onUseOnMainChart }`. Behaviour = today's review mode (drawn as
   Auto draws, endpoints and waypoint moves locked, Whole route, review
   checks) PLUS the Review page's satellite-check Retry section (a day-plan
   route with backstop 'unavailable' must keep its Retry), PLUS the footer's
   "Use on the main chart", PLUS the Save card only when C-b's flag says
   evidence is memory-only (decision 8).
   Words: map label "Plan Your Day route chart"; status "Plan Your Day route ·
   review checks, then use it on the main chart or go back."; locked-move
   reason "Change the stop in Plan Your Day; edit the route on the main
   chart."
2. **Tide chips at her leave time:** `departureMs = proposal.departureMs ??
   Date.parse(proposal.createdAt)` (:725). TodaySheet passes a clone of the
   stored proposal with `departureMs` = the chosen leave (the stop page's
   leave chip), so changing the leave time never re-routes.
3. **Contract change, said in the comment:** endpoints arrive inside the
   proposal from the skipper's explicit tap on a stop; the boat fix is the
   plan's start and appears only as the proposal's first coordinate. The
   identity fence, the draft confirmation (asked in 2 before any route) and
   the switch gate are unchanged.
4. **Mounting.** TodaySheet mounts the workspace itself with `lazyRetry`
   (as RoutingModeDialog.tsx:21 does) inside a Suspense with the "Opening
   chart…" fallback; while it is open, Plan Your Day's own overlays are
   hidden (not unmounted: state kept) and their focus traps inactive
   (`TodayModal active`). Back restores focus to the stop page's button.
   `initialDraftM`, `initialSpeedKts`, `initialVesselProfile` are taken
   exactly as RoutingModeDialog.openAuto does (:124-135). **`mapboxToken`**:
   thread it RoutePlanner.tsx (which already resolves `mapboxToken ||
   import.meta.env.VITE_MAPBOX_ACCESS_TOKEN || ''` for RoutingModeDialog,
   :1457) → DayPlannerEntry → TodaySheet. The workspace reads
   `useAutoroutingProvider()` (context default = Thalassa's provider); the
   day-planner fixture wraps it with the stub provider.
5. **"Use on the main chart" (the path to Follow; critic 2026-10-10).**
   - `PlotDayAction` gains `routed?: true`; `plotDayAction` gains an optional
     routed line: `plotDayAction(start, candidate, stay, routed?)` builds the
     same out-and-back (`pins()`, today.ts:1608-1618) from the routed
     coordinates instead of `routeCoords`, with no `savedRoute`.
   - `onUseOnMainChart` (TodaySheet) calls `setPlanDeparture(leave)` and
     `onPlot(plotDayAction(..., routedCoords))`; DayPlannerEntry already
     forwards any TracerOpenAction to `requestTracerOpen` + the chart page.
   - MapHub's 'plot-day' branch keeps its pin path for `routed` (it already
     clears the frame, :853-854) and says "Plan Your Day's route to {stop}:
     Route report is checking it; Sail follows it, Save keeps it."
   - Over PLOT_DAY_MAX_POINTS (19,999: a routed line is hundreds): one way
     only, toast says "home: Reverse route". Never straight pins.
   - It writes no `proposal_evidence` and no new store: the Manual plotter's
     draft (sessionStorage, her line) and, if she saves, its existing Save
     (line + verification words). Licence: common rule 4; decision 5.
     **One indirect store (critic pass 2):** the plotter grades the
     hundreds of legs it is handed, and today's leg-verdict cache
     (localStorage `thalassa_leg_verdicts_v4`, routeTracer.ts:2030-2066)
     keeps each leg's charted `minDepthM`/`minAt`/`nudgeTo`. 127-C-b's v5
     stubs remove that; this path therefore never ships in a build
     without C-b (both are never-cut, so this is a b127 merge-order note,
     not a gate on merging this package).
   - **The draft says where it came from.** `TraceDraftData` gains
     `draftSource: 'day-plan-route' | null` (persisted beside the frame kind,
     key `thalassa_trace_wip_source`), set by this branch for a `routed`
     action and cleared only when the draft is replaced or cleared (moving a
     pin does not clear it: the line still came from the router). 127-C-b
     reads it: if decision 5 comes back "no", the plotter's Save refuses such
     a draft over protected charts with C-b's words, while Sail still works
     (127-C-b, "If Shane says no", item 2).
   - Not for testers (no routed line exists for them).
6. **Plot by hand, and the straight hint suppressed (critic 2026-10-10,
   HIGH).**
   - `PlotDayAction` gains `frame?: { from: NamedPoint; to: NamedPoint; why:
     string }` with `points: []`; `plotDayPins` accepts it; MapHub's
     'plot-day' branch sets `traceOrigin`/`traceDest` and `traceFrameKind:
     'day-plan'` (no `setCapturedCoords`), flies to both, and flashes "{why}
     Drop pins round the land; Route report checks them." The departure is
     still set (`setPlanDeparture`) so the Route report's tide windows follow
     it.
   - **The frame's kind lives in the draft, persisted.** `TraceDraftData`
     gains `traceFrameKind: 'course' | 'day-plan' | null`, written to
     sessionStorage beside origin and destination (new key
     `thalassa_trace_wip_frame_kind`) and read back in `readDraft`. **A
     stored frame with no kind reads as 'day-plan' (fail closed; critic
     pass 2):** the course frame's boxes are parked (`COURSE_FRAME_VISIBLE =
     false`, mapHubHelpers.ts:121), so no production draft needs the hint,
     and an unreadable kind must never bring the straight line back.
     `setCourseFrame` sets 'course' explicitly. **Every path that clears the
     frame clears the kind:** useTraceDraft.ts:317-318 and :349-350, and
     MapHub's `setTraceOrigin(null)`/`setTraceDest(null)` at :853-854,
     :1980-1981 and :2773-2774 (`clearCourseFrame`); simplest is for
     useTraceDraft's `setTraceDest` setter (:251) to clear the kind whenever
     it is given null. `reverseDirection` keeps it. Persisting it is the point: a MapHub-only flag would reset to
     "show the hint" after a reload or a jetsam while the frame came back from
     sessionStorage, and the straight line with it.
   - **The hint is never drawn for a Plan Your Day frame.**
     useTracerTraceLayer gets `destHint: boolean` (MapHub passes
     `traceFrameKind !== 'day-plan'`); the hint's features come from a new
     pure, exported `destHintFeatures({ coordCaptureMode, destHint, hintFrom,
     traceDest })` that returns [] when `destHint` is false. It is called at
     the SAME place in sync() (:357-373), so nothing is reordered (the
     header's rule) and the source/layer install stays where it is.
   - **Why suppress, not restyle** (the vision's grey dashed "sketch, not
     checked" was considered): any straight segment from the boat to the stop
     crosses whatever is between them; restyled, it is still the line Shane
     complained about ("it goes direct. straight over hills"). The grey
     "sketch, not checked" style belongs to lines SHE draws off the boat
     (127-DESKMAP), not to a bearing hint. The parked course frame keeps its
     hint unchanged.
7. **Delete the straight-pin paths.** `plotDayAction` no longer builds
   [start, stop(, start)] from `routeCoords` for a non-saved stop: with no
   routed line and no saved route it returns the frame action (6). Its
   over-PLOT_DAY_MAX_POINTS fallback for a saved route becomes the frame
   action ("Your saved route is too long to plot here: open it from Saved
   Routes."). MapHub's "Straight lines to X" toast goes. The saved-route path
   stays.
8. **Save card (licence).** In the day-plan chart, Auto's Save card shows only
   when 127-C-b's `CHART_FACTS_STAY_ABOARD` (services/chartFacts.ts, C-b
   decision 1) is in b127 and true: proposal evidence memory-only (C8) and
   chart numbers off disk (C10). One condition here. A module that does not
   exist yet cannot be imported (the build fails), so whichever of C-b and
   this package merges SECOND wires it: before C-b, the condition is `false`
   with a comment naming C-b; C-b's plan already expects to switch it on
   (127-C-b, Gates: "this package, then 127-PYD-3's Save card"). Without it the
   Review page says "Save it from the main chart: Use on the main chart."
   The card's eligibility stays Auto's own `evaluateAutoroutingProposalSave`,
   which C-b extends for decision 5. Either way "Use on the main chart" is the
   path on. (The vision's lane 1 had "Its Save card waits for C-b"; that
   stands, but nothing else waits.)
