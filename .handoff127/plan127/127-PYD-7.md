## Decision (our recommendation)

1. `components/dayPlanner/TodayPicks.tsx` (new) renders `view.top`: hero =
   `top[0]` when its level is Inside or Near, else no hero (three plain rows).
   Alternates use 4's tags; the hero uses a level + BEST FIT badge.
2. Hero buttons (full tier only): Route it -> `openStop(id, { route: true,
   thenChart: true })` (the tap of decision 2: it starts 2's route exactly as
   the stop page's "Route round the land" does, through 2's queue); Details ->
   `openStop(id)` (no route). TodaySheet owns `thenChart`: when 2's route
   resolves routed and the page is still open, it opens 3's chart; if the page
   closed, 2 has already cancelled the route.
   **Route it shows only when 2's `stopRouteGate` passes** (Shane's account in
   127, switch on, signed in, her own boat). Otherwise the hero has one
   full-width button, "Details", and the stop page carries 2's one-line reason
   with its link (critic 2026-10-10: a "Route it" that can only land on "Turn
   on Auto route (trial)", or on nothing for a tester, would be the first
   thing most testers tap and the first thing that fails).
3. Tokens on `.today-main`: `--today-surface` (raised), `--today-edge`
   (level colour), `--today-border`; measured targets: surface vs card ≥ 1.25:1,
   card border vs backdrop ≥ 2:1, text on surface ≥ 4.5:1 (body) in both
   themes. Mono numerals for times only.
4. Sizes come from the 126-17b room clamps (hero name = stop name + ~10%;
   times = the 126-17b times size + ~15% in mono; floors unchanged), so the SE
   stays at today's sizes.
5. **Tiers by the room the sheet really gets (critic 2026-10-10).** The
   sheet's room is 483 / 572 / 685 / 754 px at 320x568 / 375x667 / 390x844 /
   430x932 (day-planner-layout.spec.ts:44-52). The mock's screen 1 used 670 of
   683 px at 390 x 779 as drawn with the full hero; a 375 x 667 phone has 113
   px less, and the full hero (badge, name, times, home line, shelter word, a
   44 px button row: ~170-190 px) is ~120-140 px taller than the row it
   replaces. Hero + two alternates + ribbon at full size cannot fit 572 px.
   So, by viewport height (the CSS sees the phone's real height):
   - `min-height: 740px` (390x844 → 779 as drawn, 430x932, the 1024x768
     split pane): full hero + two alternates;
   - `600px-739px` (375x667): **compact hero** ≤ 84 px (badge + name on one
     line, times + "home 15:57 · 22 NM" on the next; no buttons, the whole
     hero is the button to the stop page) + two alternates ≤ 52 px each;
   - `max-height: 599px` (320x568, phone landscape): compact hero + one
     alternate (today's two-row tier, DayPlanner.css:171-174).
   **Measure first:** before any CSS, record on b127 at 375x667 as drawn
   (`&root=app`, SF and wide fonts) the heights of header, day chips, tiles +
   facts (or 6's ribbon), headline and credit in every mode; the picks'
   budget there is 572 px minus those and the gaps, and the compact hero's
   84 px is set from it. If even the compact tier does not fit with no inner
   scroll at normal text, move the 600 px line up to 668 px (so a 375x667
   phone shows the compact hero + one alternate, as the SE does) rather than
   shrink type or let the
   alternates fall into the 126-17b inner scroll (common layout rule: fits one
   screen at 375x667 and up). Buttons stay ≥ 44 px wherever they show.
6. The tiles' old stop row CSS that no longer applies is removed, not left
   dead.
