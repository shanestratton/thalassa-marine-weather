## Decision (our recommendation)

1. **The switches** (common, "The two switches"): new
   services/dayPlanner/pydRouting.ts with `PYD_ROUTING_FOR = 'owner'`,
   `PYD_ROUTE_ON_OPEN = false`, and `pydRoutingAudience(isOwner)`. TodaySheet
   reads `sources.ownerAccount()` once per open (default
   `supabase.auth.getSession()` from services/supabase, the stored session:
   `session.user.email === PLATFORM_OWNER_EMAIL
   && session.user.id === scope.userId`; imported read-only from
   services/chat/constants.ts). Not the owner and `PYD_ROUTING_FOR ===
   'owner'` → no routing UI at all.
2. **One entry point, Auto's provider.** New services/dayPlanner/stopRoute.ts:
   - `stopRouteGate(ctx)` (pure): audience first (decision 1), then signed in,
     default boat, switch, draft confirmed, in the order of the table above,
     returning `{ ok } | { words, action? }` (action 'preferences' | 'vessel'
     | 'confirm-draft').
   - `routeStop(req, { signal, onProgress })`: dynamic
     `import('../autoroutingThalassa')`, then `calculateThalassaProposal`
     with `{ departure: start, destination: stop, draftM, speedKts,
     vesselProfile: snapshotAutoroutingVesselProfile(vessel), departureMs }`.
     Returns `{ kind: 'routed', proposal, nm, wallMs }` or `{ kind:
     'no-route', words, action?, wallMs }`. Never raw `tryInshoreRoute`, never
     the Pi's /api/enc/route, never a line on failure.
   - "No installed chart covers the …" is rewritten as the table's global
     sentence; every other provider message passes through whole, with one
     more exception (critic pass 2): Auto's `BUCKET_UNREACHABLE`
     (autoroutingThalassa.ts:82-83, "Licensed charts come only from your
     boat's Pi: sync them aboard") is also mapped to the global no-chart
     sentence when no Pi is paired (a NOAA user offline hits it after C-a
     makes `bucketAvailable` the NOAA manifest only); with a Pi paired,
     127-C-c's `boatChartsLine` words are used.
3. **departureMs through Auto's provider (not the engine).**
   `AutoroutingTrialRequest.departureMs?: number` (types/autorouting.ts:14-21)
   and `AutoroutingTrialRoute.departureMs?: number` (:86-102);
   `calculateThalassaProposal` uses `input.departureMs ?? Date.now()` (:285)
   and stamps the route; `snapshotRequest` (:120-154) validates it (finite,
   within -1 h .. +8 days of now). Auto's own calls are unchanged. This is the
   ONLY provider change in this package (the earlier draft's `dryRuns`/
   `pinTail` copies are dropped: critic 2026-10-10). No engine file changes,
   so no Pi re-sync. PYD passes the chosen leave (the stop page's chip,
   `chosenMs`, else `plan.best.departureMs`); a later leave-chip change never
   re-routes (the line is 'safest'; the tide changes when, not which way; 3
   re-stamps a clone for the tide chips, 11 recomputes its window in memory).
4. **The timing readout (decision 2; critic 2026-10-10).** `routeStop`
   measures `wallMs = performance.now()` from the tap to the result (what she
   waits through: cell loads, cloud fill, the A*, satellite check, notices).
   The route row shows, **owner only**: "Routed in {wall s, 1 dp} s · router
   {engine.elapsedMs s} s", or "No route after {wall} s". Plus ONE
   `log.warn('[pyd] route took {wall} ms, router {elapsed} ms')`, durations
   only (no positions, names or depths; common licence rule 3), so a
   connected Xcode console has it too. Shown whatever `PYD_ROUTING_FOR`
   says, so a later flip never shows testers the stopwatch.
   **With 127-C-c (critic pass 2):** C-c's `ensureBoatCells` runs inside
   the provider (before the endpoint gate and in the fill), so the provider
   also returns `chartsMs` (ensure's own `ms`) as an optional TOP-LEVEL field
   of `AutoroutingTrialRoute` (memory only, never in `engine`, so this
   package's "disclosure keys unchanged" test stays true). The owner line
   then reads "Routed in 6.4 s · charts 1.2 s · router 4.1 s". Decision 2's
   ≤ 8 s rule reads the WALL figure on the first open after a fresh launch
   (127-C-c question 2). Whichever of this package and C-c merges second
   adds the field and the middle figure.
5. **When routing starts.** `PYD_ROUTE_ON_OPEN = false` ships: the "Route
   round the land" tap (the footer button, 3; and Route it, in 7). The `true` path
   (start when a stop opens) is built and tested too; the constant is the
   only switch, set only on Shane's timings (all three ≤ 8 s).
6. **One route at a time, memory only, nothing stale (critic 2026-10-10).**
   TodaySheet keeps `routes: Map<key, RouteState>` (key = stop id | start to 5
   dp | draft to 0.01 m), state 'queued' | 'routing' | 'routed' | 'no-route',
   each with its own AbortController.
   - At most ONE route runs; at most ONE waits. A newer request replaces the
     waiting one (latest tap wins).
   - **Closing a stop page cancels its route:** a waiting one is removed; a
     running one is aborted (`controller.abort()`). The provider passes the
     signal to `tryInshoreRoute`, so the route stops at once: before the job
     is posted if it is still in the prep, else the worker job is ended
     (127-ROUTE-W decision 7), unless another caller (Auto, the planner) joined
     the same run. *(fallback: it stops at the provider's next `assertCurrent`;
     a running A* finishes and its result is dropped.)* Nothing is ever started
     for a page that has closed.
   - A stopped run leaves the engine's dedupe map at once (127-ROUTE-W
     decision 7), so re-opening and tapping never joins the run just
     cancelled.
   - A route that FINISHES while its page is open is kept for the sheet's
     life: re-opening shows it at once. Re-opening a cancelled one shows the
     button again, and a tap starts a fresh run (a stopped worker starts cold;
     a run another caller kept going is joined through the engine's in-flight
     dedupe, InshoreRouter.ts:860-873).
   - Cleared when the start changes or the sheet closes; the sheet already
     closes on an account change (TodaySheet.tsx:176-195). A result that
     arrives after close or account change is dropped (the provider's
     `assertCurrent` and the sheet's own scope check). Never written to
     storage.
7. **Route row words** from the real disclosure fields only (common), one
   line, at most two findings after the distance, in this precedence:
   1. unverified (`stateMask === null`): "not verified: recalculate in Auto";
   2. satellite check not done (`backstop === 'unavailable'`):
      "satellite land check not done";
   3. tides not loaded (`tideCheck === 'not-loaded'`): "tides didn't load:
      shallow water not cleared";
   4. shallow water: total NM of `shallowRuns` that are neither
      `endpointTail` nor `dryTail`: "0.3 NM shallow" (127-PYD-11's leave
      window says when it clears, or that nothing today does);
   5. a pin tail (`endpointTail`): "last 0.2 NM shallow" / "first 0.2 NM
      shallow"; `dryTail` on it: "the pin dries";
   6. structures unknown (`structuresUnknownCells.length`): "bridge heights
      not charted in 1 chart".
   No place names: a shallow run carries none (the first draft's "Pioneer
   Point" was invented); named dry stretches are in Auto's warnings, which 3
   shows whole. Never parse a warning sentence. Offline at sea 2 and 3 are
   the common case; say them, never a bare "Routed".
   Cautions, not blocks: the route never changes the weather verdict.
8. **Times from the routed line.** `DistanceBasis` gains 'routed'
   (places.ts:75): `{ basis: 'routed', factor: 1, straightNm, nm:
   engine.distanceNM, route: { name: '', points, lengthNm } }`.
   `DayPlanInput.routes?: ReadonlyMap<string, RoutedLeg>` feeds `planStop`
   only: routed coords for `buildRouteIndex` (real courses, so beating vs
   reaching follows the bends) and factor 1. **It never feeds `preRank` or the
   card selection**, so rows never reshuffle while she looks. The routed leg
   lives on the PLAN, never on `row.candidate.distance`: `plotDayAction`
   (today.ts:1607) reads `candidate.distance.route` and must not pick up
   hundreds of engine vertices by accident (3 hands the line over on purpose).
9. **Wind along the routed line.** TodaySheet asks `loadStopLegs` again with
   the routed coords under id `${id}#routed` (2 proxy calls; Open-Meteo quota
   is 1,200/h signed in); `planStop` prefers routed legs when present.
   Offline: no legs, so the routed distance shows and times say "no forecast".
10. **Footnote when routed:** "Route from your charts: draft 2.40 m + 0.5 m
    under the keel at chart datum; tide shown, never assumed. Home is the same
    route turned round. Times from {polar basis} in {model} wind. No current.
    Not a clearance." The route row replaces `distanceLine`'s row on a routed
    stop (What the skipper sees, 5); unrouted, it stays as today.
11. **Draft confirmation.** New reason 'day-plan' in DraftConfirmReason;
    `runWithConfirmedDraft('day-plan', start)` on the first tap on a profile
    that is not confirmed (stored on the vessel, so once). The modal must sit
    above the stop page: render the stop page's TodayModal on 'modal' while a

12. **Default boat.** No routing on DEFAULT_VESSEL (`usingDefaultVessel`).
13. **Comment hygiene.** Update the "never routes" headers (today.ts:6-8,
    TodaySheet.tsx:17-20, TodayStopDetail.tsx:34-43) and the switch comment
